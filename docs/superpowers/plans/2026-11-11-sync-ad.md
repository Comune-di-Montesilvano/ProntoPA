# Sync utenti da AD (0.9.14) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un account AD di servizio in sola lettura allinea ogni notte (e su richiesta) gli utenti dei gruppi `PRONTOPA_*`: crea, aggiorna ruolo/email, riattiva, disattiva.

**Architecture:** `Directory::membriGruppi()` legge i membri; `AllineaUtenteAd` (estratto da `LdapLoginService`) scrive l'utente, condiviso da login e sync; `SincronizzaUtentiAd` orchestra con sicurezze anti-disattivazione-di-massa; comando `ldap:sincronizza` (scheduler 05:30) + job da pulsante admin.

**Tech Stack:** Laravel 13, LdapRecord v4, Spatie Permission v6, PHPUnit (sqlite :memory:).

**Spec:** `docs/superpowers/specs/2026-11-11-sync-ad-design.md`

## Global Constraints

- Test: `MSYS_NO_PATHCONV=1 docker compose exec -T php php artisan test` (no `--parallel`); larastan `docker compose exec -T php composer run analyse`.
- Env nuove `LDAP_SYNC_USERNAME`, `LDAP_SYNC_PASSWORD` → `config('ldap.sync.username|password')`, anche in `x-php-env` di `docker-compose.yml`, in `.env.example`, e forzate vuote in `phpunit.xml` con coppia `<env force>`+`<server force>`.
- Sync spenta se `LDAP_SYNC_USERNAME` o `LDAP_SYNC_PASSWORD` vuote, salvo `LDAP_HOST=mock` (mock sincronizza i 7 utenti mock sempre).
- Ogni parametro password: `#[\SensitiveParameter]` + riga in `tests/Unit/PasswordNonNeiLogTest.php`.
- Autorizzazione via Gate/Policy, mai ruoli nel controller.
- Soglia blocco: disattivazioni > 50% degli utenti `ldap` attivi, solo se questi sono ≥ 5.
- Orario notturno `05:30`.
- Versione 0.9.14: `publiccode.yml` softwareVersion + CHANGELOG `## [0.9.14] - 2026-11-11`.

## Review Focus

1. AD restituisce elenco vuoto/troncato (base DN errato, paging) → mai disattivazioni di massa.
2. Utente ldap attivo il cui account AD è disabilitato ma ancora nel gruppo → disattivato.
3. Login dopo una disattivazione per uscita dal gruppo → resta rifiutato (nessun gruppo); login di chi è rientrato → riattivato.
4. Account `spid`/`locale` mai toccati dalla sync e ancora disattivabili a mano.
5. Gestore che diventa admin: tiene tipologie esplicite, perde `gestore_tutte_tipologie`.
